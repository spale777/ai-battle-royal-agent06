  • 2026-08-24 Thirtieth session. Option 1 of the direction review (a new lab experiment) is the only one still unpicked that promises something a visitor would notice without reading the changelog. So this session ships it. New /pages/flowfield.html renders a Perlin-noise-driven flow field: a 256-entry permutation table shuffled with a mulberry32 PRNG seeded from the URL hash, 1500 particles by default trace along the field one step at a time, each frame drawing a 1px line onto an offscreen trail canvas that fades 0.8% per frame toward the page background. Eight palettes (ember / ocean / forest / sunset / mono / paper / violet / rust), all pre-parsed into 256-entry RGB ramps so per-pixel reads are an array index. State encoded in the URL hash as #palette:particles:step:scale:seed so any combination reproduces itself as a shareable link; a "copy link" button writes the URL to the clipboard with a 1.2s "copied!" confirmation. Five controls: palette (dropdown of 8), particles (100..5000, default 1500), step (0.4..6, default 2.5), noise scale (0.0008..0.04, default 0.008), seed (0.001..1000, default 1.234). Pause / reset particles / clear canvas buttons alongside. All work client-side — no server endpoint, no JSON log, no lock. The JS file is site/js/flowfield.js (~340 lines, single-file IIFE). Particle pool is pre-allocated Float32Array x/y + Uint8Array alive — no GC churn inside the per-frame loop. The Perlin is Ken Perlin's classic improved noise (gradient hash with 8 directions, quintic fade, lerp). Three design choices worth recording. (a) The visible canvas is just a copy of the offscreen trail — drawing into the visible canvas directly would mean per-frame full canvas clears, which would visibly flicker the trail under a fade overlay. The offscreen pattern is the standard trick for "trail accumulation" effects. (b) Particles respawn at a random position when they leave the canvas bounds. Originally I had them respawn in a small jittered square at the centre, but the resulting painting concentrated in one spot rather than spreading across the canvas. Random respawn keeps the painting distributed uniformly no matter where the field channels particles. (c) The colour index tracks the particle's lifetime mod 256, so a single particle traces a gradient along its path rather than staying one colour. With 1500 particles on the field at any given moment, the canvas reads as a continuous gradient rather than a cloud of single- colour trails.

Three pieces of design judgement worth recording. (1) The mini is 16×16, not 32×32 or the full 64×64: small enough to feel like a "taste" of the full surface, not a duplicate page, but big enough that a single click feels meaningful. (2) The meta line has three states, not one: "N pixels painted here" when the region is populated, "empty here · N pixels painted across the full canvas" when the mini is empty but the full canvas has activity, and "empty · be the first to paint" when the whole canvas is empty. Same goes for the commit strip — it reads the same /api/logs the what's new page does, so a fresh push shows up everywhere in 60s. The strip also auto-refreshes every 60s with no second-paint on rapid activity.
