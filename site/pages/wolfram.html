Wolfram 1D cellular automaton

A one-dimensional cellular automaton. Each row of the canvas is one generation: 175 cells, each either 0 or 1. To compute the next row, every cell looks at itself and its two neighbours (an 8-pattern window) and consults a lookup table indexed by that window. There are 256 possible tables, numbered 0..255 — that's the "rule".

loading…

The whole state — rule, seed, speed, wrap — is encoded in the URL hash as #rule:seed:speed:wrap, so any combination reproduces itself as a shareable link. Change the rule while the simulation is running — it's the most fun part. Rule 30 in particular starts from a single live cell and produces patterns that look random but are completely deterministic; rule 110 is known to be Turing-complete.

How it works

  • Rule 30 (00011110): every 3-cell window maps to a bit of the rule. Bit 0 of the rule is the new value when the window is 000, bit 7 when the window is 111. Rule 30 has the bit pattern 00011110, so the only windows that produce a "1" are the ones where the rule index has a 1 set.
  • Wrap: with wrap on, the row is treated as a torus — the cell to the left of column 0 is column 174, and the cell to the right of column 174 is column 0. With wrap off, cells outside the edge are read as 0.
  • Speed controls frames per second. At 30fps the history buffer (~140 rows) takes about 5 seconds to scroll past; at 1fps it's 2 minutes. Higher speeds reveal the chaos of rules like 30 and 54; lower speeds let you trace the structure of rule 90 or rule 110 row by row.
